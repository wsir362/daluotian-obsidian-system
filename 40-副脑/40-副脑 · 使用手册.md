# 40-副脑 · 使用手册

## 核心设计：三层调用系统

文件夹膨胀不是问题，**没有调用路径**才是问题。

40-副脑 不靠文件夹层级来组织，而是靠 **三层调用系统**：

```
第一层：类型文件夹（粗筛）
    ├── 心智模型/     ← 决策框架、思维模型
    ├── 洞察与原则/   ← 关于人/系统/规律的判断
    ├── 策略与方法/   ← 可执行的操作指南
    ├── 术语词典/     ← 概念的通俗解释
    └── 原文索引/     ← 承接永久笔记 source 回链

第二层：YAML 元数据（精筛）
    ├── domain: 人性与认知 / 内容与传播 / 商业与创业 / ...
    └── tags: 识人 / 信任 / 决策 / 危机 / ...

第三层：MOC 主题索引（聚合）
    └── 把跨类型、跨 domain 的相关笔记串成主题地图
```

---

## 调用方式详解

### 方式1：按类型找（粗筛）

你知道自己在找什么"类型"的笔记：

- 想找一个**思维框架** → 打开 `心智模型/`
- 想找一个**关于人的判断** → 打开 `洞察与原则/`
- 想找一个**操作方法** → 打开 `策略与方法/`
- 想搞懂一个**概念** → 打开 `术语词典/`

每个文件夹里的文件按文件名排序，标题都是自解释的（如"恩义排序""信任溢价"），一眼扫过去就能定位。

### 方式2：按领域/标签找（精筛）

每个笔记的 YAML frontmatter 都有 `domain` 和 `tags`：

```yaml
---
type: 洞察
domain: 人性与认知
tags:
  - 识人
  - 信任
  - 组织
---
```

**domain** 是大分类（固定几个）：人性与认知、内容与传播、商业与创业、职场与进阶、品牌与营销、思维与方法论

**tags** 是自由标签（按需添加）：识人、信任、决策、危机、人设、IP、粉丝、边界...

在 Obsidian 里：
- 搜索 `domain:人性与认知` → 只显示这个领域的笔记
- 搜索 `tag:识人` → 显示所有打了"识人"标签的笔记（不管在哪个文件夹）
- 搜索 `tag:信任 tag:决策` → 交集筛选

### 方式3：按主题找（聚合）

MOC（Map of Content）是主题索引卡，不存放内容，只放链接：

```markdown
# 识人 · MOC

## 心智模型
- [[价值排序识人法]]

## 洞察
- [[恩义排序]]
- [[责任排序]]
- [[真实排序]]
- [[边界排序]]

## 术语
- [[信任溢价]]

## 相关 MOC
- [[信任 · MOC]]
- [[决策 · MOC]]
```

**关键**：一个笔记可以被多个 MOC 引用。
- `价值排序识人法` 既在 `识人 · MOC` 里，也可以在 `决策 · MOC` 里
- `信任溢价` 既在 `识人 · MOC` 里，也可以在 `IP运营 · MOC` 里

这就是**双向链接**的力量：笔记只存一次，但可以从无数个主题入口找到它。

### 方式4：图谱漫游（发现）

Obsidian 的 Graph View（图谱视图）会显示所有笔记的链接关系。

当你积累了一定数量的笔记后，打开 Graph View：
- 输入 `tag:识人`，只看这个标签的笔记和它们的关联
- 你会发现两个看似无关的笔记其实有隐藏联系
- 这就是**第二大脑的涌现价值**

## 为什么文件夹不分更细？

因为**分类是树的，思维是网的**。

如果一个洞察同时属于"人性"和"决策"，你把它放哪个子文件夹？
- 放 `人性/` → 从 `决策/` 路径找不到
- 放 `决策/` → 从 `人性/` 路径找不到
- 复制一份放两边 → 同步更新噩梦

**解决方案**：
- 文件夹只分"类型"（心智模型/洞察/策略/术语），这是**唯一分类**
- 原文索引只存来源入口，不复制工作区拆解内容
- 用 `domain` 和 `tags` 标记领域和主题，这是**多维标签**
- 用 MOC 做主题聚合，这是**网状链接**

一条笔记可以在无数个 MOC 里被引用，但物理文件只存在一次。

## 数量级预估

| 类型 | 预估数量 | 调用方式 |
|------|---------|---------|
| 心智模型 | 50-100 个 | 标题自解释 + 类型筛选 |
| 洞察与原则 | 300-500 个 | tags 精筛 + MOC 聚合 |
| 策略与方法 | 100-200 个 | domain 筛选 + tags 精筛 |
| 术语词典 | 100-200 个 | 标题首字母排序，像查字典 |

即使 `洞察与原则` 里有 500 个文件，你也不会直接打开文件夹去翻。
你会：
1. 先想"我要找什么主题？" → 打开对应的 MOC
2. 或者搜索 `tag:识人` → 只显示 20 个相关笔记
3. 或者搜索 `domain:人性与认知 tag:信任` → 进一步缩小到 5 个

---

## 维护规则

1. **每新建一条笔记，必须填 YAML**：type / domain / tags，不然后续找不到
2. **每提取一组笔记，必须建 MOC**：否则笔记之间无法产生连接
3. **每月回顾一次 Graph View**：看看有没有孤立的笔记（没有入链也没有出链的），补上链接
4. **工作区处理完即归档**：原文拆解文件不进主库，避免污染

---

## 快速启动

现在你可以用这几种方式测试调用：

1. 打开 `洞察与原则/` 文件夹 → 看到 4 个文件，标题一目了然
2. 在 Obsidian 搜索栏输入 `tag:识人` → 显示 5 个笔记
3. 打开 `MOC/价值排序识人法 · MOC.md` → 一键直达所有相关笔记
4. 打开 Graph View → 看到笔记之间的链接关系
