# Hooks · 触发手册

> 本目录下的所有 hook 均为「检查清单」，需要在特定时机手动读取并执行。
> 当前版本尚无自动化触发器，依赖 AI 助手在对应场景下主动调用。

---

## Hook 清单

| Hook | 触发时机 | 作用 | 执行方式 |
|------|---------|------|---------|
| `pre-sync.md` | 执行任何批量文件同步/移动**前** | 拦截常见错误（路径、重复、类型） | 同步开始前，AI 主动读取并逐项检查 |
| `post-sync.md` | 执行任何批量文件同步/移动**后** | 验证同步结果（根目录、重复、md缺失） | 同步结束后，AI 主动读取并逐项验证 |
| `weekly-review.md` | **每周五**（或用户主动要求"复盘"时） | 回顾纠正、提炼规则、评估健康度 | AI 读取并生成复盘报告，用户确认后写入 memory |
| `today-archive.md` | **每天首次启动时**（或用户说"归档 Today"时） | 把 Today/ 下昨天及之前的文件归档 | AI 读取 Today/，按规则判断去向并执行 |

---

## 快速调用指令

对 Kimi Code 说以下指令即可触发对应 hook：

```
"执行同步前检查" → 触发 pre-sync.md
"执行同步后验证" → 触发 post-sync.md
"执行每周复盘"   → 触发 weekly-review.md
"归档 Today"      → 触发 today-archive.md
```

---

## 与 AGENTS.md 的衔接

在 `AGENTS.md` 的快速启动流程中，第 4 步「触发 hooks」应在以下场景执行：
- 用户要求"同步桌面文件" → 先 pre-sync → 执行同步 → 后 post-sync
- 用户要求"复盘" → weekly-review
- 每天首次交互 → 检查 Today/ 是否需要归档
