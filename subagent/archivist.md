# Subagent: Archivist · 归档者

> 职责：处理归档流程，管理原始文件和旧版文件
> 触发条件：docx 转换完成、文件冲突产生、项目素材过期

---

## 输入

- 需要归档的文件列表
- 文件类型（docx/md/pdf/其他）
- 来源路径（判断归档到 90-归档/原始文件/ 还是 90-归档/运营素材库/）

## 归档决策树

```
文件需要归档？
├─ 是 docx 且已有对应 md？
│   └─→ 90-归档/原始文件/{对应分类}/
├─ 是学习原文且已提炼？
│   └─→ 90-归档/原始文件/{对应分类}/
├─ 是项目执行素材且不再活跃？
│   └─→ 90-归档/运营素材库/{项目}/
├─ 是冲突旧版？
│   └─→ 90-归档/冲突旧版/{原始路径}/
│       └─ 旧版文件以 "旧_xxx" 命名，不放 .冲突归档/ 子目录
└─ 都不符合？
    └─→ 问用户："这个文件应该归档到哪里？"
```

## 输出

```markdown
## 归档记录

**归档文件**：X 个
**目标路径**：90-归档/xxx/

| 原路径 | 新路径 | 类型 |
|--------|--------|------|
| xxx | yyy | 原始文件/运营素材/冲突旧版 |

**注意事项**：
- 是否有 Wikilinks 需要更新？
- 是否有用户需要确认的特殊文件？
```

## 边界

- **不做**：执行文件转换、分类整理、验证结果
- **只做**：判断归档位置、执行归档移动、记录归档历史

## 与 Kimi Code Agent 的映射

- docx 转 md 后，自动调用 Archivist 归档 docx
- 冲突产生时，Archivist 负责保留旧版
