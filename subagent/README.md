# Subagent · 路由表

> 本目录定义了大罗天项目的四种角色分工。
> 实际调用时，AI 助手应根据任务类型自动路由到对应角色规范。

---

## 路由表

| 任务类型 | 判定标准 | 调用角色 | 流程 |
|---------|---------|---------|------|
| **简单文件操作** | 涉及文件 < 3 个，目录 < 2 个，无复杂依赖 | `executor.md` | 直接执行 → 调用 validator.md 验证 |
| **复杂任务** | 涉及文件 ≥ 3 个，或多目录联动，或需拆分步骤 | `planner.md` → `executor.md` → `validator.md` | 先规划 → 用户确认 → 执行 → 验证 |
| **docx 转 md 后** | 完成 docx→md 转换 | `archivist.md` | 判断归档位置 → 执行归档 → 记录 |
| **批量操作后** | 完成任何批量移动/删除/分类/同步 | `validator.md` | 按验证清单检查 → 生成报告 |
| **产生冲突/旧版** | 文件覆盖或版本冲突 | `archivist.md` | 保留旧版 → 按规则命名 → 记录 |

---

## 角色速查

| 角色 | 职责 | 不做的事 |
|------|------|---------|
| `planner.md` | 拆分任务、制定计划、预估风险 | 不执行文件操作、不验证、不归档 |
| `executor.md` | 执行具体文件操作（移动/复制/删除/创建） | 不规划、不验证、不归档 |
| `validator.md` | 检查结果、发现遗漏和错误 | 不执行修复、不修改文件 |
| `archivist.md` | 处理归档流程、管理原始文件和旧版 | 不执行转换、不分类整理 |

---

## 与 Kimi Code Agent 的映射

当前 Kimi Code 环境中可用的 subagent 类型：
- `coder` → 映射到 `executor.md`（执行文件操作）
- `plan` → 映射到 `planner.md`（制定计划）
- `explore` → 用于快速探索代码/文件库（无对应角色，属于通用能力）

**建议**：在复杂任务开始时，AI 助手应自我声明：「本任务触发 Planner 角色，按 planner.md 规范执行」。
