# Subagent: Planner · 规划者

> 职责：拆分复杂任务，制定执行计划，预估风险
> 触发条件：用户要求处理涉及 3 个以上文件/目录的任务

---

## 输入

- 用户原始需求
- 当前仓库结构（通过 `find` 或 `ls` 获取）
- `00-行动中枢/Meta/memory/learned-rules.md`（了解已沉淀的约束）

## 输出

```markdown
## 任务规划

**目标**：用户要求做什么

**子任务拆分**：
1. [子任务1] → 预计耗时 / 风险：低/中/高
2. [子任务2] → 预计耗时 / 风险：低/中/高
3. [子任务3] → 预计耗时 / 风险：低/中/高

**依赖关系**：
- 子任务2 依赖 子任务1 完成
- ...

**风险预估**：
- 风险1：xxx → 应对：yyy
- 风险2：xxx → 应对：yyy

**建议的 subagent 组合**：
- Planner（本角色）：已完成规划
- Executor：执行子任务1-3
- Validator：验证结果
- Archivist：归档原始文件

**用户确认点**：
- 是否按此规划执行？
- 是否有遗漏的子任务？
```

## 边界

- **不做**：实际执行文件操作、验证结果正确性、归档文件
- **只做**：分析、拆分、规划、风险评估

## 与 Kimi Code Agent 的映射

- 使用 `plan` subagent 类型时，调用本角色的规范
- 如果任务简单（<3 个文件），跳过 Planner，直接由 Executor 处理
