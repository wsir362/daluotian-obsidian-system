# 模型路由表

> 本文件是轻量路由表，用来替代启动阶段直接读取完整 `AI决策助手.md`。AI 工具应先根据本表判断问题类型和候选模型；只有本表不足以支持分析时，才读取完整模型库。

## 使用规则

1. 用户提出具体问题后，先读取本文件。
2. 根据问题类型选择 1-3 个候选模型。
3. 如果本文件已经足够完成分析，不要读取 `AI决策助手.md`。
4. 如果必须读取完整模型库，只允许读取一次，并说明读取原因。
5. 不要为了“更完整”而反复读取 `AI决策助手.md`。
6. 如果问题属于新媒体执行任务，先判断是否需要决策；不需要决策时转交 `../造化司/`，本系统只保留必要的判断结论。

## 问题类型路由

| 问题类型 | 判断信号 | 优先模型 | 是否需要完整模型库 |
|---|---|---|---|
| 个人重大选择 | 辞职、转行、学习路线、人生规划、A/B选择 | 机会成本分析、决策树/OODA、苏格拉底提问法 | 通常不需要 |
| 商业/创业判断 | 赛道、市场、商业模式、赚钱逻辑、竞争 | 商业模式画布、SWOT/TOWS、波特五力、TAM/SAM/SOM | 复杂市场问题才需要 |
| 产品/增长/私域 | 用户增长、私域、留存、转化、功能优先级 | AARRR、北极星指标、JTBD、RICE、价值主张画布 | 通常不需要 |
| 新媒体运营决策 | 账号定位取舍、是否追热点、产品卖点选择、投放/转化路径判断 | GTM、AARRR、价值主张画布、OODA、合规风控检查 | 需要先判断时使用本系统，执行转交 `../造化司/` |
| 新媒体执行 | 写脚本、改文案、做选题、追热点、内容优化、生成成品 | 不在本系统展开模型分析 | 不需要完整模型库，直接转交 `../造化司/` |
| 风险评估 | 值不值得做、投入产出、止损、失败概率 | 风险矩阵、情景规划、贝叶斯更新、安全边际 | 复杂风险才需要 |
| 团队协作 | 沟通困难、分工混乱、职责不清、推进受阻 | RACI/RAPID、苏格拉底提问法、谬误识别、钢人化原则 | 通常不需要 |
| 知识库整理 | 归类、模板、规则、系统优化、沉淀 | 奥卡姆剃刀、分类规则、MOC、PDCA | 通常不需要 |

## 输出格式路由

| 用户意图 | 默认输出 |
|---|---|
| “帮我分析” | 结构化分析结果 |
| “给我方案” | 行动方案 + 优先级 |
| “保存进系统” | 保存到 `案例/` |
| “保存成模板” | 保存到 `模板/` |
| “沉淀成规则” | 建议写入 `40-副脑/` 或系统规则，修改前先说明 |
| “后续复盘” | 保存到 `复盘/` |
| “写脚本/改文案/做选题” | 转交 `../造化司/`，成品按总控台回链项目资产 |

## 最小分析格式

当问题较轻时，不必读取完整模型库，直接用以下格式输出：

```markdown
## 问题定义

## 选用模型

## 关键判断

## 行动建议

## 风险提示

## 置信度
```

## 读取完整模型库的触发条件

只有出现以下情况，才读取 `AI决策助手.md`：

1. 用户明确要求“从完整模型库里选模型”。
2. 问题横跨多个复杂领域，本表无法判断。
3. 用户要求比较多个高级模型的适用性。
4. 需要引用完整模型库中的具体模型定义。

读取后必须遵守：

```text
本 session 中不要重复读取 AI决策助手.md。
如果已经读过，基于已有上下文继续工作。
```
