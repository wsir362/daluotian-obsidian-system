# AI入口协议

> 本文件是「大罗天 · AI决策中枢」的通用入口。Codex、Claude Code、OpenCode、KimiCode、ChatGPT 等 AI 工具进入本系统时，都应先读取本协议。
> 上位裁判：`../00-行动中枢/Meta/系统文档/大罗天系统总控台.md`

## 系统定位

大罗天 · AI决策中枢不是某个 AI 工具的专属项目，而是一套基于 Obsidian 本地文件的个人分析决策工作流。

核心原则：

```text
文件是系统本体
协议是调用入口
AI 是执行器
案例是资产
复盘产生复利
变更日志记录演化
```

## 轻启动顺序

AI 工具进入本系统时，先执行轻启动，不要一开始读取完整模型库。

1. 读取 `AI入口协议.md`：理解本协议和执行边界。
2. 简短告诉用户：系统已准备好，请输入具体问题。
3. 等用户输入问题后，再判断是否需要读取其他文件。

不要在用户提出具体问题前读取完整的 `AI决策助手.md`。它是模型库，不是启动文件。

## 按需读取顺序

用户输入具体问题后，再按以下顺序选择性读取：

1. 先读取 `模型路由表.md`：判断问题类型、候选模型和输出位置。
2. 必要时读取 `README.md`：确认系统用途和目录结构。
3. 只有路由表不足以支持分析时，才读取 `AI决策助手.md`：选择更完整的分析模型、确认模型定义。
4. 根据任务类型，选择性读取相关目录：
   - `../40-副脑/`：心智模型、洞察、术语、策略方法。
   - `../造化司/`：新媒体执行层。只有当问题需要脚本、文案、选题、热点、内容优化等执行产出时调用。
   - `../00-行动中枢/`：日常任务、行动记录、工作流。

不要一次性读取整个知识库。优先读取说明文件、MOC、文件名列表，再根据问题选择少量相关笔记。

## 上下文节省规则

1. 启动阶段只读取 `AI入口协议.md`。
2. 用户输入问题后，优先读取 `模型路由表.md`，不要直接读取完整 `AI决策助手.md`。
3. 一个 session 中最多读取一次 `AI决策助手.md`。
4. 如果已经读取过 `AI决策助手.md`，后续不得重复读取，必须基于已有上下文工作。
5. 不要为了“更完整”而读取无关目录。
6. 输出普通建议时，优先使用最小分析格式，避免长篇套模板。

## 三层分工

```text
40-副脑 = 知识资产层
50-AI决策系统 = 分析决策层
造化司 = 新媒体执行层
```

### 40-副脑

用于调用长期知识资产，包括心智模型、洞察与原则、策略与方法、术语词典、MOC 主题索引。

### 50-AI决策系统

用于接收问题、判断类型、选择模型、输出分析、保存案例、安排复盘。

边界：

- 负责“该不该做、怎么取舍、风险在哪里”。
- 不负责直接批量生产脚本、文案、选题成品。

### 造化司

用于处理新媒体运营相关任务，包括账号定位、内容生产、产品卖点、电商转化、合规风控、数据复盘。

边界：

- 负责“怎么写、怎么改、怎么产出”。
- 如果任务只是写脚本、改文案、做选题、追热点，直接转交造化司。
- 如果任务需要先判断账号方向、产品取舍、风险边界，先在本系统完成决策分析，再交给造化司执行。

## 支持的问题类型

第一版优先支持以下 6 类问题：

1. 个人重大选择：职业、学习、项目取舍、人生规划。
2. 商业/创业判断：商业模式、市场机会、竞争策略。
3. 产品/增长/私域问题：产品定位、用户增长、私域运营、转化路径。
4. 新媒体运营判断：账号定位取舍、是否追热点、产品卖点选择、转化路径、合规风险。
5. 风险评估：项目风险、资源投入、不确定性、止损条件。
6. 知识库整理与系统优化：目录调整、模板设计、规则沉淀。

## 标准工作流

```text
用户提出问题
→ 明确问题类型
→ 判断是否需要补充信息
→ 读取模型路由表.md
→ 必要时读取 AI决策助手.md，且只读一次
→ 选择 1-3 个分析模型
→ 选择性调用 40-副脑
→ 如需内容执行，转交造化司
→ 输出结构化分析
→ 生成或更新案例文件
→ 如需长期验证，进入复盘目录
→ 如修改系统结构，更新 CHANGELOG.md
```

## 输出位置规则

所有输出必须进入明确位置，避免散落。

| 输出类型 | 存放位置 |
|---|---|
| 待分析问题 | `Inbox/` |
| 正在分析的中间稿 | `分析中/` |
| 已完成分析案例 | `案例/` |
| 未来复盘事项 | `复盘/` |
| 模板 | `模板/` |
| 系统级变更记录 | `CHANGELOG.md` |
| 新媒体执行成品 | 转交 `../造化司/`，再按总控台回链项目资产 |

## 保存语义规则

用户说“保存进系统”时，默认保存到 `案例/`。

只有用户明确指定时，才保存到其他位置：

| 用户表达 | 保存位置 |
|---|---|
| 保存进系统 / 存一下 / 归档这次分析 | `案例/` |
| 保存成模板 / 以后复用这个流程 | `模板/` |
| 做后续验证 / 之后复盘 | `复盘/` |
| 沉淀成规则 / 写进知识库 | 先说明建议位置，再征求确认 |

普通案例分析不更新 `CHANGELOG.md`。

## 案例命名规则

案例文件建议使用：

```text
YYYY-MM-DD-问题关键词.md
```

示例：

```text
2026-05-13-示例运营方案.md
2026-05-13-是否进入滋补品赛道.md
```

## 分析要求

执行分析时必须遵守：

1. 不编造数据。缺数据时先提问，或明确标注为假设。
2. 不同时调用超过 3 个模型。
3. 优先使用用户已有知识库，而不是泛泛输出通用建议。
4. 所有结论标注置信度：高 / 中 / 低。
5. 输出必须包含可执行行动，而不是只给概念解释。
6. 涉及新媒体、广告、健康、金融等内容时，必须加入风险与合规检查。

## 变更日志规则

修改以下内容时，必须更新 `CHANGELOG.md`：

1. 新增、删除或调整目录。
2. 新增或修改模板。
3. 修改入口协议、模型库、工作流规则。
4. 改造脚本或自动化入口。

普通案例分析不写入 `CHANGELOG.md`，只保存到 `案例/`。

## 跨工具使用方式

在任意 AI 工具中，可以使用以下指令启动：

```text
请读取 /Users/wsir/codex/大罗天/50-AI决策系统/AI入口协议.md，并按协议执行。
```

如果工具不能直接读取本地文件，则手动复制以下文件内容作为上下文：

1. `AI入口协议.md`
2. 用户的具体问题
3. 必要时再复制 `AI决策助手.md` 或与问题相关的少量知识库笔记

## 执行边界

第一版不做：

1. 不做全自动向量数据库。
2. 不做长期后台服务。
3. 不默认读取整个 Obsidian Vault。
4. 不把普通分析记录写进变更日志。
5. 不把输出散落到系统目录之外。
