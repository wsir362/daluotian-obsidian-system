# R1-R5 可验证性纪律

> 每个产出物都必须可验证，不能靠"感觉还行"

---

## R1: 产出物必须写入文件

**规则**：每个 phase 的产出必须写入对应文件，不能只输出在聊天里。

**验证方式**：检查 `sessions/[任务名]/` 下是否有对应文件。

---

## R2: 每个 phase 必须有验收清单

**规则**：phase 完成后，必须用对应 checklist 逐项检查。

**验证方式**：检查 checklist 是否逐项打勾。

---

## R3: 三角度 prompt 必须做一致性检查

**规则**：3 个版本的 prompt 必须通过一致性检查表，核心卖点不能矛盾。

**验证方式**：检查 consistency-check.md 是否填写完整。

---

## R4: 内层迭代必须有质量阈值

**规则**：每轮迭代产出必须达到质量阈值才能进入下一轮。

**质量阈值**：
- 标题吸引力 ≥ 7/10
- 卖点清晰度 ≥ 8/10
- 情绪共鸣度 ≥ 7/10
- 转化路径完整度 ≥ 8/10

**验证方式**：每轮迭代后打分，低于阈值重新迭代。

---

## R5: 终稿必须经过对比合并

**规则**：终稿不能直接用某一轮的产出，必须经过逐模块对比合并。

**验证方式**：检查 comparison-table.md 是否填写完整，终稿是否标注了来源。

---

## 违反处理

| 违反规则 | 处理方式 |
|---------|---------|
| R1 产出未写入文件 | 立即补写，重新执行该 phase |
| R2 未做验收 | 立即补验收，有问题则返工 |
| R3 未做一致性检查 | 立即补检查，卖点矛盾则重新设计 prompt |
| R4 迭代超 5 轮 | 暂停，人工介入判断 |
| R5 未做对比合并 | 立即补做，重新输出终稿 |

---

*可验证性是这套工作流的核心，没有验证 = 没有完成。*
