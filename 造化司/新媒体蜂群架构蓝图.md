## 0. 当前裁判规则

本蓝图描述的是造化司的理想架构，不代表所有目录和 Agent 已经启用。

当前 v0.1 执行规则：

1. `造化司/` 是新媒体执行器，不是平行知识库。
2. `造化司/memory/` 只做任务索引和专用缓存，长期知识资产回到 `10-项目/` 或 `40-副脑/`。
3. `造化司/sessions/` 存内容生产过程。
4. `造化司/output/` 存成品暂存；长期使用的成品必须回链或复制到 `10-项目/道物天成/内容资产/`。
5. 需要判断“该不该做、怎么取舍、风险在哪里”时，先进入 `50-AI决策系统/`；需要写脚本、改文案、做选题时，再进入造化司。

## 三、Subagent 角色定义

### 3.0 Coordinator · 新媒体总监

**文件位置**：`造化司/agents/coordinator.md`（规划中，当前未创建）

**核心职责**：
- 接收你的模糊需求，拆解成任务图
- 调度其他 Agent，决定执行顺序
- 汇总各方输出，解决冲突，拍板决策

**调度逻辑**：
```
用户需求 → Coordinator 分析
  ├─ 需要起号/定位？ → 调起号策略 Agent
  ├─ 需要内容产出？ → 调内容生产 Agent
  ├─ 涉及带货/转化？ → 调电商转化 Agent
  ├─ 涉及产品卖点？ → 调产品卖点 Agent
  ├─ 所有内容出厂前？ → 调合规风控 Agent
  └─ 需要复盘优化？ → 调数据复盘 Agent
```

**冲突解决规则**：
- 电商说"太软没转化" vs 内容说"太硬没流量" → Coordinator 根据阶段目标拍板
- 起号期：内容优先（涨粉为主）
- 稳定期：转化优先（变现为主）

### 3.1 起号策略 Agent

**文件位置**：`造化司/agents/account-strategy.md`（规划中，当前未创建）

**职责**：账号定位、竞品分析、人设打造

**Prompt 核心**：
```
你是账号定位专家。你的任务是：
1. 分析目标赛道的竞品账号（头部3个、腰部3个、新号3个）
2. 提炼差异化定位（人设、内容风格、变现路径）
3. 输出「账号定位画布」：
   - 一句话定位
   - 目标用户画像（年龄/痛点/场景）
   - 内容三件套（选题方向/标题公式/封面风格）
   - 变现路径（带货/广告/私域）
   - 30天起号节奏表
```

**挂载资源**：
- 竞品分析模板（Memory Store）
- 历史起号案例（Memory Store）

---

### 3.2 内容生产 Agent

**文件位置**：`造化司/agents/content-producer.md`（规划中，当前未创建）

**职责**：选题、文案、脚本、标题

**Prompt 核心**：
```
你是内容生产专家。你的任务是：
1. 基于「卖点+转化路径」生产具体内容
2. 输出格式：
   - 标题（3个版本：情绪版/数据版/悬念版）
   - 正文/脚本（分段标注：钩子/卖点/促单）
   - 封面文案（6字以内核心钩子）
   - 评论区引导（3条预埋评论）

关键约束：
- 所有内容必须通过「电梯测试」：用户刷到15秒内能记住核心卖点
- 必须包含「情绪钩子」：前3秒必须引发好奇/共鸣/争议
```

**Session 解耦用法**：
- 一条视频 = 一个独立 Session 文件夹
- 可 Fork：同一选题产出 A版（情绪向）和 B版（测评向）
- 爆了的内容 → Clone Session 给其他 Agent 复盘

### 3.3 电商转化 Agent

**文件位置**：`造化司/agents/e-commerce.md`（规划中，当前未创建）

**职责**：带货逻辑、促销话术、转化路径

**Prompt 核心**：
```
你是电商转化专家。你的任务是：
1. 设计「流量钩子→卖点植入→促单指令→转化路径」完整链路
2. 输出格式：
   - 前3秒钩子（引发停留）
   - 中段卖点（场景化证明）
   - 尾段促单（限时/限量/赠品）
   - 转化路径（评论区/橱窗/私域/直播）

关键约束：
- 所有促单话术必须通过「电梯测试」
- 必须考虑「价格锚点」和「信任背书」
```

**挂载资源**：
- 历史爆款文案库（Memory Store）
- 促销日历/库存数据（需手动更新）

### 3.4 产品卖点 Agent

**文件位置**：`造化司/agents/product-selling-points.md`（规划中，当前未创建）

1. 把技术文档转化为用户能懂的语言
2. 输出格式：

**挂载资源**：

### 3.5 合规风控 Agent

**文件位置**：`造化司/agents/compliance.md`（规划中，当前未创建）

**职责**：平台规则、违禁词、风险审查

**Prompt 核心**：
```
你是合规审查官。你的任务是：
1. 检查所有内容是否符合平台规则
2. 检查项：
   - 虚假宣传（"最好""第一""100%有效"）
   - 极限词（违反广告法）

   - 风险等级（红灯/黄灯/绿灯）

   - 修改建议

关键约束：
- 你有一票否决权
- 红灯内容必须修改后才能发布
```

**挂载资源**：
- 平台违禁词库（需定期更新）

### 3.6 数据复盘 Agent

**文件位置**：`造化司/agents/data-review.md`（规划中，当前未创建）

**职责**：投流数据、内容数据、优化建议

**Prompt 核心**：
```
你是数据分析师。你的任务是：
1. 分析内容数据（播放/点赞/评论/转化）
2. 输出格式：

   - 对比分析（vs 历史均值/竞品）

- 建议必须可执行（具体到标题怎么改、卖点怎么调）
```

## 四、Skill 调度逻辑

### 4.1 新媒体总监调度 Skill

**文件位置**：`skill/新媒体总监调度.md`

**调度流程**：
```
1. 读取用户需求
2. 判断任务类型：
   ├─ 起号/定位类 → 调起号策略 Agent
   ├─ 内容产出类 → 调内容生产 Agent
   ├─ 带货/转化类 → 调电商转化 Agent
   ├─ 产品相关类 → 调产品卖点 Agent
   └─ 复盘/优化类 → 调数据复盘 Agent
3. 所有内容产出 → 必须经过合规风控 Agent
4. 汇总各方输出 → 解决冲突 → 输出最终方案
```

**冲突解决模板**：
```markdown
## 冲突记录

**冲突方**：电商转化 Agent vs 内容生产 Agent
**冲突点**：[具体分歧]
**各方理由**：
- 电商：[理由]
- 内容：[理由]

**Coordinator 决策**：[拍板结论]
**决策依据**：[为什么这么定]
```

## 六、Session 管理机制

### 6.1 Session 文件夹结构

```
造化司/sessions/
├── 2026-05-12-新品X起号方案/
│   ├── README.md           ← 任务描述、参与Agent、状态
│   ├── 竞品分析.md         ← 起号策略 Agent 产出
│   ├── 卖点提炼.md         ← 产品卖点 Agent 产出
│   ├── 转化路径.md         ← 电商转化 Agent 产出
│   ├── 内容方案.md         ← 内容生产 Agent 产出
│   ├── 合规审查.md         ← 合规风控 Agent 产出
│   └── 冲突记录.md         ← Coordinator 记录
├── 2026-05-13-视频脚本A/
│   └── ...
└── ...
```

### 6.2 README.md 模板

```markdown
# [任务名称]

**创建时间**：2026-05-12
**状态**：进行中/已完成/已归档
**目标**：[一句话描述]

## 参与 Agent
- [x] 起号策略 Agent
- [x] 产品卖点 Agent
- [ ] 电商转化 Agent
- [ ] 内容生产 Agent
- [ ] 合规风控 Agent
- [ ] 数据复盘 Agent

## 产出物
- [竞品分析.md](竞品分析.md)
- [卖点提炼.md](卖点提炼.md)
- ...

## 关键决策
- [决策1]
- [决策2]
```

### 6.3 Session 操作

| 操作 | 说明 | 场景 |
|------|------|------|
| Fork | 复制一个 Session，产出不同版本 | A/B 测试：情绪版 vs 测评版 |
| Clone | 复制 Session 给其他 Agent 分析 | 爆款内容复盘 |
| Rollback | 回滚到某个中间状态 | 方向推倒重来 |
| Archive | 归档到 `90-归档/` | 任务完成 |

## 七、落地步骤（零代码版）

### 第一步：建立 Memory Store（本周）

1. 在 `40-副脑/策略与方法/` 下创建：
   - `产品手册/`
   - `爆款文案库/`
   - `平台规则库/`
2. 把现有资料按 YAML 规范整理进去
3. 每个文件加 `agent:` 标签，标记关联的 Agent

### 第二步：写 Agent Prompt（下周）

1. 在 `造化司/agents/` 下创建 7 个 Agent 定义文件
2. 每个文件包含：职责、Prompt、挂载资源、输出格式
3. 参考上面的 Prompt 核心，根据你的实际需求调整

### 第三步：写 Coordinator 调度逻辑（第三周）

1. 在 `skill/` 下创建 `新媒体总监调度.md`
2. 写清楚：什么需求调谁、冲突怎么解决、输出什么格式
3. 可以复用现有的「智囊团」结构

### 第四步：跑通第一个 Session（第四周）

1. 选一个具体任务（比如"新品X起号方案"）
2. 按调度逻辑，依次调用各 Agent
3. 把过程产出物存到 `造化司/sessions/` 下，成品存到 `造化司/output/` 并回链项目资产
4. 记录冲突和决策

### 第五步：迭代优化（持续）

1. 每周复盘：哪些 Agent 输出质量高？哪些需要调 Prompt？
2. 把经验沉淀到 `learned-rules.md`
3. 逐步补充 Memory Store
